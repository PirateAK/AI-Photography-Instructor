# AI Photography Instructor — project conventions

## Stack
- Frontend: React 18 + TypeScript + Vite (frontend/), zustand for state, no UI library (custom CSS in src/styles.css, dark Apple-inspired theme).
- Backend: FastAPI (backend/), managed by uv at repo root (pyproject.toml, .venv). Python 3.11+. fastapi pinned >=0.115,<0.116 (starlette 1.7/httpx2 TestClient deadlocks in this sandbox — do not unpin).
- Single source of truth: data/camera_models.json (32 cameras incl. body hotspots; body types: dslr/mirrorless/vlog/phone — vlog = no viewfinder: ZV-E10 II + Z30; phone = generic "Phone — point & shoot" brand "Phone": fixed f/1.7 single aperture option, Pro-mode ISO 50-3200 (usable_max 800) + shutter ladder, no mount → lens selector hidden (mountOf returns null for phones), lens dropped from lensByCamera on switch, phone silhouettes in CameraBody; aperture options = full f/1.4-f/22 1/3-stop mount ladder on every body — kit-zoom limits live in the lens sim, not the body); data/shooting_styles.json (22 genres — 10 original + underwater/food/concert/real_estate/pet/family/wedding/automotive/aerial/black_and_white/travel/product — editable via Style Manager UI + /api/styles; styles can carry guided lessons array: AI-drafted ones have draft:true and stay learner-invisible until approved in Style Manager); data/training_courses.json (29 courses / 150 lessons in 4 categories — authored class lead the catalog: beginner-class (11), intermediate-class (13, paid), advanced-class (12, paid), pro-class (12, paid, Specialized), then fun classes shoot-the-moon/following-the-rainbow/northern-lights (paid), then 10 genre playbooks (wedding-event, wildlife, food, pet, sports, macro, fashion, travel, underwater, conceptual — all paid), then legacy courses (3 free teasers incl. free-exposure-triangle priority-first arc, portrait/street/night-celestial/fine-art/commercial/post-processing genre courses, nikon-school + online-workshops HIDDEN via hidden:true and filtered from Classes screen); nikon-school-course and online-workshops-course editable but hidden); data/lenses.json (34 lenses across EF/RF/E/Z — lens swap sim); data/holidays.json (8 holidays 2026–27: Halloween/Thanksgiving/Christmas/NewYear/Valentines/Easter/MothersDay/July4th — date rules incl. nth-weekday + computus, banner path, greeting, tips, challenge, 4 drilldowns; windows = 7 days before → 1 day after; ?holiday=YYYY-MM-DD URL param previews any season); data/app_config.json (store_url = https://muskegman.com — user's real business site (MuskegMan Photography: sells photos + Pro-Photo_Sorter software via Gumroad); stub redemption_codes NIGHT2026/PORTRAIT-PRO unlock ALL paid). Frontend imports directly (vite fs.allow covers ../); styles + courses also load from GET /api/styles + /api/courses on app start to pick up live edits. Adding a camera/lens/style/class = JSON edit or in-app UI.
- Run via ./start.sh (APP_PORT frontend, APP_PORT+100 backend, vite proxies /api). Devguard block required. Backend has no --reload: restart start.sh after backend changes.
- Tests: pytest at repo root (pythonpath=["."], tests/conftest.py isolates runtime_settings.json AND photo-history DB per-test; styles/courses admin tests re-point their data paths to tmp copies — never hit real AI APIs, never touch real data files), vitest in frontend/tests/. Mock coach + chat replies deterministic. CI: GitHub Actions .github/workflows/ci.yml runs pytest + tsc + vitest on push/PR — LIVE, green on every push.

## Engine/provider architecture (LIVE: user's Gemini key configured)
- backend/coach: mock.py (deterministic numpy heuristics + keyword chat), openai_provider.py, gemini_provider.py (REST, header auth x-goog-api-key — key must NEVER go in URLs, httpx logger pinned WARNING in main.py). All validate analyze against pydantic schema; chat is plain text. Both AI providers expose generate_json() (used by style + course drafting).
- Gemini specifics: model default "gemini-flash-lite-latest" (self-updating alias; 0.9s; "gemini-flash-latest" routes to a thinking model that times out — treat "gemini-2.0-flash" and "gemini-flash-latest" as legacy in _resolved()). maxOutputTokens 8192 (2048 truncates the JSON). _extract_json strips fences + slices outermost braces. _generate retries 5xx twice (free-tier 503s).
- Engine resolution: runtime_config (Setup page, runtime_settings.json gitignored, key masked in API) > env. Failures fall back to mock with visible notice; /api/settings POST rebinds without restart (RLock).

## Interactive features
- Holiday system (lib/holidays.ts + HolidayCard.tsx + banner swap): during a holiday window the home banner swaps to that holiday's art (frontend/public/images/banners/, Nano Banana via scripts/generate_holiday_banners.py) and clicks into the coach instead of muskegman.com (no image loaded → demo photo first). Coach pane shows the HolidayCard above chat: greeting seeds chatMessages when empty, challenge goal + tips + drilldown chips (each chip prefills askCoach). Accept → activeChallengeId persisted (survives the window until dismissed); every successful analyze while active → noteChallengeShot (challengeAfterShot); 3 shots → completedChallenges → 🎉 card + challenge badge (kind "challenge" in badges.ts, shown in Progress trophy case). Overlap rule: on the holiday date itself that holiday wins, else most-recent window start (Christmas yields to New Year Dec 26). Store partialize += activeChallengeId, challengeShots, completedChallenges. Backend /api/analyze + /api/chat take optional challenge form field (main.py _parse_challenge, never 400s); cache key folds challenge id into the version slot; AI providers get photo_challenge in _context_payload with CHALLENGE RULE in SYSTEM_PROMPT (goal takes precedence over style-mismatch); mock prepends "🎯 Challenge …" to chat. ?holiday=YYYY-MM-DD URL param previews any season.
- Content moderation (backend/coach/moderation.py): dedicated Gemini vision pass — runs FIRST in /api/analyze (422 "CONTENT_BLOCKED: …" before the coach, cache or provider, ever sees the photo), at /api/moderate (called by loadFile + GalleryPanel pick/capture so flagged photos never enter the coach OR the device gallery), and again server-side in /api/challenge/submit (client check not trusted). Fail-closed on flag, fail-open on engine errors/outage (never blocks legit photographers; verdicts cached by image hash, ~512 entries). Gemini-only by design — OpenAI-only configs skip the check. Terms: family-friendly only (no nudity incl. artistic, no minor sexualization, no extreme gore, no illegal content; medical/breastfeeding pass). store.contentBlocked → Workspace swaps the image pane for a 🚫 blocked-notice; goUpload clears it. Terms text lives on the About panel (📜 Content terms) + /api/moderate returns a terms summary.
- Challenge contest (backend/challenges.py + ChallengeScreen.tsx + lib/stamp.ts): shared per-holiday contest in data/challenge_entries.db (gitignored) — SUBMIT (3/device, during window, Coach score travels with entry) → VOTE (7 days after window closes, top 3/device, own entries rejected, replaceable) → RESULTS (podium + vote counts until next holiday window opens, then auto-pruned). Server stores/serves ONLY 640px JPEG thumbs — full-res originals never leave the device; entry imgs have no-download CSS guards. Submission auto-saves the original into the device IndexedDB gallery and records challengePhotoByEntry (entryId→galleryId, persisted) so a placed winner can be stamped client-side (stampPhoto: gold rosette top-right with score + "COACH RATED", small app credit bottom-right, 🥇/🥈/🥉 place banner) and re-shared (sharePhotoBlob: files→text→clipboard; message includes app link + muskegman.com). Entry points: HolidayCard "🏅 Submit this shot"/gallery link, home contest-strip during voting/results, "challenge" screen route in App.tsx. Gallery cards have 📤 share buttons (buildGalleryShareMessage). Phases computed client-side (lib/holidays.ts contestSchedule) AND enforced server-side (same rules; python weekday() is Monday-based — JSON uses JS Sunday-based, convert with (wd+6)%7).
- On-device phone gallery (GalleryPanel, shared by UploadScreen + Workspace): 🖼️ Gallery toggle button on home; 🖼️ count button in workspace header opens the wheel as an image-pane overlay (full-screen sheet ≤980px) for in-coach photo swaps; 🖼️ Pick photos (multi-select via OS picker) + 📸 Camera (capture="environment", shoots straight into coach); photos persist in IndexedDB (frontend/src/lib/gallery.ts, cap 100 oldest-evicted, thumbs 320px JPEG with Image-decode fallback + placeholder tile — shots never dropped silently, skipped count alerted); UI = single vertical wheel of cards — native drag-scroll, horizontal swipe trims (touch-action pan-y, 72px threshold, undo toast 6s), tap loads blob → File → loadFile + close overlay; renders 10 cards per page, IntersectionObserver sentinel feeds more; IDB transactions: thumbs prepared before tx opens, fresh tx per operation.
- Home-screen style picker is a one-row wheel (UploadScreen StyleWheel): 5 chips per row, headline genres (portrait/wildlife/sports/landscape/wedding) first via orderedStylesForWheel in lib/styles.ts, ▲/▼ arrows roll rows with wrap-around; clear-chip moved into the description line.
- Camera body viewer: image-pane tab, 6 views, hotspots in camera JSON body.blocks; hotspot click → toolbar highlight; setting change → hotspot flash.
- ImageViewer: live histogram, draggable focus dot (measured against viewerRef rect; dims when aperture >= baseline). Upload → toolbar initializes from EXIF as-shot (snapToCamera); Reset returns to as-shot. Histogram is clickable → HistogramGuide training overlay replaces coach-pane content (coach stays mounted — chat/lesson state preserved; Escape or ✕ returns to session). Guide shows enlarged histogram + describeHistogram verdicts (clipping/lean/spread from lib/histogram.ts) and ±1 EV "try it" buttons (exposure_comp via clampEv) that shift the live histogram in real time. histData lives in store (transient, set by ImageViewer render).
- Lens swap sim (data/lenses.json + lib/lenses.ts): lens selector in toolbar filtered by mount (mountOf derives EF/RF/E/Z from body line — Canon R-series regex); lens replaces camera's aperture options; focal-zoom framing vs EXIF focal (clamp 1-4x; wider clamps to 1 honestly); IS raises shake threshold 4 stops; setLens clamps impossible apertures + logs tip. lensByCamera persisted.
- Lessons: difficulty chips (lesson.difficulty ?? course.level) + in-course filter; completion ✓ circles + "Mark complete" (store.completedLessons persisted); course cards show progress bars; Progress screen has curriculum section (courseProgress).
- Coach chat, guided lessons (LessonPlayer), Style Manager (AI drafting via provider.generate_json; ✨ Generate lessons with AI → POST /api/styles/generate-lessons returns draft lessons for a saved style — review UI approves/discards/edits, upsert persists via the lessons field on the style; coach-pane buildLessons includes approved style lessons with step values snapped to the camera via snapValue in lib/camera.ts), Course Manager (CourseManagerScreen: CRUD + AI course draft + contributor template download + author credit; backend/courses_admin.py validates and backs up).
- Instructor Dashboard (hidden): type an instructor code (data/app_config.json instructor_codes, default INSTRUCTOR2026) into the home screen's "What do you want to learn or shoot?" field → unlockInstructor persists instructorUnlocked (partialize), navigates to InstructorDashboard hub (links to Style + Course managers, 🔒 re-lock). 🛠 button appears on home when unlocked. Camera/lens in-app editing explicitly deferred (parked with website packs). Content-management gating: Classes screen Manage styles/courses buttons grayed+🔒 for locked users (copy says "Upgrade to Pro-user" — NEVER mention the dashboard/code to users); route guard in App.tsx blocks locked access; single gate = canManageContent() in lib/training.ts (instructorUnlocked now; OR-in Pro/credits later). Future: accounts/login + upgrade page; locked features will click-through to account/upgrade section.
- Progress: per-device photo history (backend/history.py SQLite at data/photo_history.db gitignored) — auto-save after every successful analyze; same device+image_hash UPDATES row; GET list with 320px thumbnails; DELETE scoped to device; deviceId = crypto.randomUUID persisted.
- Style KB drives: recipe card, weighted score penalties, deterministic recommendation rules, style drills first. Stale persisted styleId resets on reload. Course catalog reload also resets stale styleId.

## Key design decisions
- Mobile-verified devices (published URL): Moto G Power 5G (2024, Android 15) — primary reference, layout/wheel/interactions confirmed; Galaxy Note 5 (2015-era) + Galaxy A21 (budget tier) — full passes, broad Android compatibility confirmed; iPhone 16 Pro + iPhone 15 Pro (iOS Safari) — full passes, cross-platform confirmed. All 6 phone-matrix devices passed (iPhone 15 Pro last, tested against the published deployment).
- Mobile-verified on Moto g Power 5G (2024), Android 15 — user confirms layout, style wheel, and interactions work well on a small Android screen. Keep this device as the responsive test reference.
- Simulation baseline = EXIF (iso/shutter/aperture/focal) else camera defaults; gain = log2((t/t0)(ISO/ISO0)(N0/N)^2)+EV. DoF only when opening wider than baseline. Motion smear below 1/60s (raised by IS). WB presets/kelvin → temp/tint shifts. Picture styles → contrast/saturation/sharpen/mono.
- Coach tips for setting changes are deterministic text (lib/tips.ts), NOT AI calls. Cache: LRU+TTL keyed by sha256(image)+camera+settings+style+intent.
- Apply-to-simulator no-op detection: logs "already match your setup" instead of silently doing nothing.
- Persist via zustand partialize: cameraId, settingsByCamera, beginner, intent, styleId, unlockedCourses, deviceId, lensByCamera, completedLessons. Image/chat/highlight/focus not persisted.
- ErrorBoundary wraps every screen. Backend serves frontend/dist as SPA if it exists. Accepted cuts: composition notes are luminance heuristics, DoF mask is radial, history is per-device (no accounts), variable-aperture zooms simulated at their wide-end range.
