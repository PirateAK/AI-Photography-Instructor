## 3. NARRATION SCRIPT

**Welcome**

Amateurs lose files; professionals build systems where losing them requires six mistakes at once. This lesson is the professional's version of the Intermediate workflow — scaled for shoots where the images can't be re-taken.

**Card discipline: the moment of maximum risk**

The most dangerous moment is the transfer. The card is the only copy in existence. The professional rules: import before anything else, import to two destinations when the shoot matters, verify the copies (count and spot-check) BEFORE considering clearing the card — and then don't clear it until delivery is done. A formatted card is a decision, not a habit.

**Working files: naming and structure that scales**

The Intermediate naming habit scales up: dated project folders, originals in their own folder never touched, working files beside them, exports separated. Add the professional layer: a client code in the folder name, and a structure identical across every project — because a system you don't have to think about is a system you keep under deadline pressure.

**The 3-2-1 backup habit**

Three copies of every image, two different media, one off-site. The working drive, the backup drive, and the off-site copy — cloud or a drive that lives elsewhere. Backups run on schedule, not on memory. And a backup you've never test-restored is a hope, not a backup: restore one folder occasionally and prove the system.

**Demonstration: card to working to backup**

The bakery shoot's card, live. Import to the working drive — originals land untouched in the project's originals folder. Count verified against the card's file count; three frames spot-checked full size. Copy to the backup drive; count verified again. The card goes in the pocket, unformatted, until delivery. Working files created beside the originals with the client code and date. Total time: minutes. Total risk of loss: one card, which still exists.

**Version control: killing "final_final_v2"**

Working edits get versioned by structure, not by filename chaos: the editor's project file holds the history; exports are named by purpose and date — "bakery_web_2026-10-12". When the client asks for changes, the same export name gets a new date, never a new suffix. Old versions don't get deleted; they get superseded. The folder tells the story in order, and "which version is final" always has one answer: the latest date in the exports folder.

**Learner practice**

Run one real shoot's files through the full professional path — card to verified import to working structure to 3-2-1 backup — and time it. Then test-restore one folder from the backup and confirm it opens.

**Recap**

Card discipline first: import, verify, and never format until delivery. Working structure that scales: dated, coded, originals untouched. Backups by 3-2-1 on a schedule, tested by restoring. And versioning by structure and date — "final_final_v2" is the sound of a system that doesn't exist.

## 6. LEARNER PRACTICE

Run one shoot's files through the professional path:

1. Import from card to the working drive; originals untouched.
2. Verify: file counts match; spot-check three frames full size.
3. Copy to the backup drive; verify the count again. Card stays unformatted.
4. Create the working structure with client code and date; version exports by purpose and date.
5. Test-restore one folder from the backup and confirm it opens.
Time the whole path. If it's too cumbersome to repeat every shoot, simplify the system — a workflow you skip is the one that fails.

## 7. RECAP

The transfer is the moment of maximum risk: import, verify, and never format until delivery. Working structure scales — dated, coded, originals untouched, exports separated. Backups run 3-2-1 on a schedule and get test-restored. Versioning lives in structure and dates, not filename chaos. Professionals are judged by what they don't lose.

## 8. ACCURACY CHECK

- Cloud and backup software behavior varies; demonstrate only the tools filmed.
- 3-2-1 is the industry's common baseline, not a legal requirement — present it as the dependable habit.
- File-count verification depends on the import tool's reporting; show the actual method used.
- Do not claim any system is loss-proof; the lesson's premise is reducing simultaneous failure points.
- Verify all on-screen folder names and counts are legible and match the narration.
